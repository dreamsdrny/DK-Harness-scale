# 对话滚轮缩放 / Conversation Wheel Zoom

`@local/ui-wheel-zoom` —— 用鼠标滚轮**只**缩放 DeepSeek Harness 的对话区域，侧边栏、页头和其他界面保持原样。

## 怎么用

- **Ctrl + 滚轮**（macOS 为 ⌘ + 滚轮）：放大 / 缩小对话区域，一步约 10%
- **直接在小胶囊上滚动滚轮**：不需要按 Ctrl
- 右下角小胶囊：`−` / `+` 微调，点击中间的百分比回到 100%
- 范围 50% – 200%，缩放值记在浏览器本地，刷新后保留

## 为什么改成了"只缩放对话区域"

整页缩放（`html { zoom }`）会把侧边栏、标题栏一起放大，阅读长回答时反而不方便。现在只给对话转录区加 `zoom`：里面的字号、内边距、图标、按钮等**绝对长度**一起放大，而百分比宽度仍按布局给的值，所以消息只会重新排版并继续纵向滚动，不会把列撑出横向滚动条。左侧导航、页头、输入框保持 100%。

## 实现

- 目标用**几何定位**，不依赖输入框位置：取窗口中部（左边缘不在左侧导航带上）、宽度 ≥ 窗口 30%、高度 ≥ 320px 的最大可滚动盒子，也就是对话转录区。
- 左侧导航（会话列表、工作区列表）贴着窗口左边缘，永远不满足条件，所以始终保持在 100%。
- 空对话还没有滚动容器时，退化为 `conversation.composer.dock` 里 0×0 锚点的最近祖先（同样排除贴左边缘、接近整窗宽的外框）。
- 如果这次 Chromium 连盒子的百分比尺寸一起放大，插件会把转录区钉回所在列的大小，避免溢出到输入框。
- 目标在切换 Session / 打开设置时会被卸载重建，插件只在目标脱离 DOM 时重新解析并重新应用（1.2s 定时检查）。
- 小胶囊注册在 `shell.overlay` 插槽，只用 `--dsw-alias-*` 主题令牌；它不在被缩放的区域里，所以大小恒定。
- Ctrl + 滚轮监听在 `window` 上且显式 `passive: false`；已被其他控件 `preventDefault()` 的组合键不抢。
- 文案走客户端 locale 服务的 `ui-wheel-zoom` 命名空间（en / zh）。

## 已知限制

- 缩放以转录区左上角为基准，不跟随鼠标锚点。
- 本地值存在 `localStorage`，以当前页面来源（含端口）为准；如果桌面端每次启动换端口，缩放会回到 100%。
- 目标通过 DOM 几何推断（宿主未提供专用的缩放插槽）；若宿主大幅调整对话骨架，可能需要更新 `findTranscript` 的判据。
